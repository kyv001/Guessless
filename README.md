# Guessless

一个不靠运气的扫雷：雷不是开局前固定埋好的，而是每次翻开后，从所有与已知数字一致的局面里重新选择一个。数字不会骗你，输赢基本取决于推理。

## 与常规扫雷的区别

- **没有预先固定的雷区**：第一次点击时才生成雷，并避开点击格及其周围 8 格（棋盘足够大时保证首击开 0）。之后每翻开一格，都会维护"所有与已翻开数字一致、且总雷数正确"的候选局面集合。
- **猜，只在没有安全走法时被允许**：
  - 点到所有候选局面里都是雷的格子 → 输；
  - 存在至少一个必安格，却去点一个不确定的格子 → 输；
  - 没有任何必安格时才允许强制猜；系统会选一个与点击格相容的局面并翻开它。若前沿还有不确定格，强制猜只能在前沿进行。
- **旗子没有语义**：不参与任何判断，也不要求插对；它只用于 chord——点击已翻开的数字时，若周围旗数等于数字，就把其余未插旗邻居按顺序当成手动点击批量执行。
- **会分析内陆格**：已翻开数字只直接约束前沿；内陆格只受剩余雷数影响，可以被推导为必安，或作为剩余雷的候选。
- **胜利条件**：未翻开的格子数恰好等于总雷数时获胜——此时剩余格在模型里都只能是雷，安全格已经全部翻开。

## 背后的模型

把未翻开格分成两类：

- **前沿格 F**：与某个已翻开格相邻的未翻开格；
- **内陆格 I**：其余未翻开格。

用布尔变量 `x_u ∈ {0,1}` 表示格 `u` 是不是雷。每个已翻开的数字 `n_c` 给出线性约束：

```text
Σ_{u ∈ N(c) ∩ F} x_u = n_c
```

再加上总雷数：

```text
Σ_{u ∈ F} x_u + Σ_{u ∈ I} x_u = n_mines
```

求解器用回溯枚举前沿格的赋值，检查上述约束，并保证剩余雷数能放进内陆格。每个可行解记录"前沿哪些是雷"和"内陆还剩几颗雷"。

由此可以判定：

- 前沿格：在所有解中都是雷 → **必雷**；都不是雷 → **必安**；有的解是、有的解不是 → **不确定**；
- 内陆格：所有解都不在内陆放雷 → **全必安**；所有解都恰好放满内陆 → **全必雷**；否则只能视为剩余雷的候选。

真正翻开一个格子时，系统会均匀地选一个可行解，再在内陆候选格中均匀放置剩余的雷，然后用这份"选中的世界"计算新翻开格子的数字并扩散翻开。因此棋盘始终和已翻开的数字保持一致。

最坏情况下前沿有 `k` 个格子，枚举复杂度是 `O(2^k)`；约束和总雷数边界会大量剪枝，普通棋盘上通常够快。
